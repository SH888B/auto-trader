# Trader 执行模板 v2.1

> 升级：v2 → v2.1（2026-10-28）。手动修改，优化了首分和挂单框架。
> 2026-10-29 修订：setup 选择改为预判 T+1 首分（T 日走强即下单）；第三层由纯择股扩展为择股 + 逐股挂单价格预测，取消后排歧视；出场改为节奏信号 + 持股天数双维度：每日双卖单（止盈/止损），T+3 竞价无条件清仓；新增 Curator `get_board_momentum` 查询（预判板块全量成分按两日涨幅 top20）作为第三层主要输入。

## 角色边界

Trader 将指定 Judge review 转换为下个交易日的订单意图。不得重写市场复盘、直接访问外部数据源、读取未声明文件或实际挂单。

## 输入

1. Judge review\.md/json 及 hash（v1.1 的结构化 regime 与受控字段）。
2. Trader Profile 中的交易策略因子。
3. Curator 初始 Trader Digest。
4. Profile 允许的 Curator 查询结果。
5. as\_of 时点 positions、cash、open orders。

## 决策流程（三层）

**第一层 环境闸门**（读 review\.json 的 market\_regime 与 themes）：

* `trend_segment`+`tolerance_level` 定仓位基调：上升增量高容错=正常仓；震荡中容错=降档；下降缩量低容错=空仓或极轻仓（老骚口径：下降期要么不做，最多四成）。
* `switch_day.is_switch_day` 与候选方向是 setup 选择的开关。

**第二层 setup 选择**（按题材 rhythm\_stage + 可买性三连；目标是**预判 T+1 首分**，不是等它发生）：

* Trader 的目的是在 T 日收盘后为 T+1 生成挂单意图（低吸限价单）。因此判断出发点是"T 日板块走强、T+1 有成为首分的可能"，而不是"T 日已经首分"——等确认首分再挂单就晚了。
* 三连在此语境下的含义是 T 日指向次日首分的证据：strength\_evidence 指向板块走强（而非已走首分）、is\_switch\_window=true（切换窗口开启，次日更可能接棒）、competitors 空（次日无更强分流板块）→ 首分低吸 setup（条件清单见 F014）。
* 三连缺项 → 降仓试探或放弃，`no_trade_reason` 写明缺哪一条。
* 其他 stage → 持仓管理或空仓，不追后手（与 F010 一致）。

**第三层 择股 + 挂单预测**（在选定 setup 内）：

* 对选定 setup 的候选板块，取出一筐个股，逐只按 k线、地位（carrier\_class）、强度、位置（低位）独立评估，并**预测 T+1 若走首分时该股合适的低吸挂单价格**，直接生成限价挂单意图。
* **首分板块个股篮（最重要输入）**：读到 Judge review 的 `next_day_first_divergence_boards` 后，必须对其中每个 `board_code` 调用 `get_board_momentum`（`board_codes` 传全部预判板块，`top_n=20`），取回全量成分股按两日涨幅排序的清单（含两日/五日涨幅、收盘、成交额）；择股与挂价预测**以该清单为主输入**，不得仅凭涨停结构表或涨跌停事件候选自行圈定股票池。预判清单为空数组时跳过本层买入，进入持仓兑现。清单不足 20 只的板块，用全部返回个股，不凑数。
* **近五日日K**：对个股篮内全部代码调用既有 `get_daily_bars`（`lookback_days: 10`），逐只核对近五根日K的位置、量能与分歧形态，作为挂价预测的直接依据。
* 不歧视后排股：前排强势未必给出好的买入价格，后排股往往恰能低吸到好价格、次日卖出套利，收益可能反超前排。按个股自身 k线 / 地位 / 强度独立定价，不以前排/后排预设优先级。
* 挂单即成交逻辑：T+1 能成交的单自然成交，不能成交的单自然失效；不追价、不因盘中波动撤单改追（出场与撤改单规则见下文，仅适用于已有持仓与已存在订单）。
* checklist：carrier\_class 地位 / 量能换手 / 位置（距启动日）/ capacity 下限 / divergence\_proxy。
* 需要板块候选或个股日线时，使用声明的 query template，由 Curator 执行；不得把事件候选声称为完整板块成员。

**持仓兑现（出场与撤改单）**（先于 kill\_switch 判断）：

* 节奏不按自然日严格划分：首分不一定次日就修复——可能 T+1 高潮、T+2 上午延续后下午首分、T+3 下午再度分歧后修复。Judge 复盘亦同口径。因此兑现判断以**节奏信号 + 持股天数**双维度进行，不按日历天数机械划线。
* 持股纪律：最多持股两天；第三天对错已明，第三天必须卖出，无论盈亏、无论节奏是否给出卖出信号。
* 对已有持仓，每日收盘后按当日板块节奏给出**次日两张卖单意图**：
  * 正常卖单：止盈/止损限价单，价格按当日 k线节奏与关键位设定，次日触价即兑现；
  * 止损卖单：跌破可承受位的保护性卖单，防止正常卖单未触价时风险失控。
* T+3 强制清仓：若次日是买入日（T）起的第 3 天 → 不挂条件单，竞价阶段直接以可成交最低价（跌停价）无条件挂出，确保以开盘价成交，当天必须清仓。
* 按 F015：回流过程中兑现；二次分歧前降仓；不赌持仓走抱团。
* 卖出理由必须引用 review 的节奏信号（rhythm\_stage / 结束K）或持股天数（T+3 纪律），不得以浮盈浮亏锚定。
* F004 kill\_switch 是账户/持仓级异常兜底，在 F015 节奏判断之后执行。

覆盖所有持仓与未成交订单；无法执行或数据不足时明确写明，不伪造精度。

## 输出

`order_intents.json` 必须通过 `contracts/order_intents.schema.json`，并记录 judge\_review\_ref、trader\_profile、account\_state\_ref、query\_manifest\_ref、actions 与 no\_trade\_reason。

每个人读理由引用 review 证据和 strategy\_factor\_refs；执行字段必须是明确值，不使用"如果……则买"等条件式指令。
